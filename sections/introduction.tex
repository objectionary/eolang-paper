\section{Introduction}\label{sec:introduction}

Object-oriented programming is the dominant paradigm in industrial software
  development, yet its mainstream realisations carry a long list of features
  that have nothing to do with objects as such.
Class hierarchies, static methods, implementation inheritance, mutable
  state, \nospell{NULL} references, operators, type casts, reflection,
  flow-control statements built into the syntax, and primitive scalar
  types --- each of these complicates programs and obscures the
  object-as-actor metaphor on which OOP rests.
A language that took the object as its single primitive and rejected
  every feature that is not strictly necessary would lay bare what OOP
  actually \emph{is}.
EO is such a language.

EO has no types, no classes, no static methods, no implementation
  inheritance, no \nospell{NULL}, no global scope, no type casting, no
  reflection, no mutability, no scalar primitives, and no operators.
Every entity in an EO program is an \emph{object} ---
  a formation of named attributes ---
  and the only mechanism for reusing behaviour is \emph{decoration}:
  one object binds another to its special attribute \(\varphi\)
  (written \ff{@} in source), and attribute dispatches that find no local
  match fall through to the same dispatch on the decoratee.
There are no control-flow keywords;
  conditionals, loops, and sequences are themselves objects defined in
  the standard library.

The formal grounding of EO is the \(\varphi\)-calculus
  introduced by \citet{bugayenko2021eolang}.
The \(\varphi\)-calculus describes object formation, application,
  dispatch, and dataization with a small set of reduction rules;
  EO is a surface syntax for the same model with significant whitespace,
  two equivalent notations for application (horizontal and vertical), and
  conveniences such as method chains, reversed dispatch, compact tuples,
  and inline-phi formations.
The translation from EO to \(\varphi\) is the bridge between the surface
  programmer can write and the calculus over which proofs and program
  transformations can be carried out.

This paper specifies EO precisely enough that two independent
  implementations can agree on which programs are well-formed and on
  the meaning of each well-formed program.
Its contribution is a single end-to-end contract:
  a lexical layer, a surface syntax classifying every legal line and
  multi-line composition, the cross-line rules that decide which
  compositions are accepted, and a translation function
  \(\llbracket\,\cdot\,\rrbracket\) from accepted programs to
  \(\varphi\)-calculus expressions.
The structural layout that delivers this contract is summarised in
  \cref{sec:preamble}, which states what each chapter contains,
  suggests reading orders for different audiences, distinguishes
  normative from informative material, and fixes the typographic
  conventions used throughout.
